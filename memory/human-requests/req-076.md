# REQ-076 — `ai:sync` com a lista canônica antiga das skills de governança

- **Origem**: pedido do Humano (Otávio) em 14/10/2026, a partir do fechamento do BATCH-280 do core.
- **Relacionada**: [REQ-075](req-075.md) (renomeação para MDD) / BATCH-077.
- **Topologia sugerida**: `dupla`; o agente-chefe classifica e decide o lote.

## Sintoma

No core, `vendor/bin/phpunit` falha em um teste desde o commit `7f8edac5` (REQ-075):

```
MemoryDualReq266Test::testSyncRequiresAll45SkillsAcrossTheFiveKits
- 1 => '45/45',  + 1 => '41/45'
- 3 => '✔ Complete',  + 3 => '⚠ Incomplete'
```

## Causa

Os cinco kits (`.claude`, `.codex`, `.cursor`, `.gemini`, `.github`) têm as 45 skills, já com os nomes MDD. A lista canônica em `conn2flow/cli/src/Commands/AiSyncCommand.php` (linhas ~20-78) ainda declara os quatro nomes antigos:

| Na lista do `AiSyncCommand` | Nos kits (REQ-075) |
| --- | --- |
| `continue-sdd-batch` | `continue-mdd-batch` |
| `sdd-memory-gardening` | `mdd-memory-gardening` |
| `sdd-workflow` | `mdd-workflow` |
| `start-sdd-slice` | `start-mdd-slice` |

Por isso o `c2f ai:sync` acha 41 das 45 skills esperadas em cada kit e marca todos como incompletos.

## O que fazer

1. Trocar os quatro nomes na lista do `AiSyncCommand` (core) e conferir se a fonte canônica do `ai-workspace` usa os mesmos nomes.
2. Conferir os outros lugares que listam skills por nome (índices, `skills/README`, CLAUDE.md/AGENTS.md dos satélites) e os aliases `sdd-*` que ainda existem em alguns satélites (no site ainda aparecem `continue-sdd-batch`, `sdd-workflow`, `start-sdd-slice` e `sdd-memory-gardening` na lista de skills do agente).
3. Rodar `vendor/bin/phpunit --filter MemoryDualReq266Test` no core (referência: `ssh lab`) e `c2f ai:sync` nos satélites.

## Critérios de aceite

- [ ] `MemoryDualReq266Test` verde no core.
- [ ] `c2f ai:sync` mostra `45/45 ✔ Complete` nos cinco kits.
- [ ] Decisão registrada sobre manter ou remover os aliases `sdd-*` nos satélites.
