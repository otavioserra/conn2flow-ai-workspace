# REQ-079: Motor de Banco de Dados MDD (`SQLite3 + FTS5` Local e Multi-Driver SQL) no `mdd-client`

## 1. Contexto e Objetivo
Evoluir o cliente Python do ecossistema MDD (`tools/mdd-client/` no `conn2flow-ai-workspace`) para incorporar um **Motor de Banco de Dados Relacional e Full-Text Search BM25 (`SQLite3 + FTS5`)** local (`memory/.mdd.sqlite`), com **Storage Driver Abstrato** compatível 1:1 com a tabela relacional `ai_memories` e `ai_memory_links` do módulo universal `ai-memory` (`conn2flow-site` / futuro Core `conn2flow`).

Assim, tanto os agentes de desenvolvimento local quanto aplicações SaaS multiusuário (como a Fábrica de Vídeos `c2f-media` e os módulos de IA do Gestor) passam a consultar, indexar, relacionar e registrar aprendizados MDD via banco de dados estruturado além dos arquivos `.md`.

---

## 2. Escopo Técnico Obrigatório (`BATCH-081`)

### 2.1. Módulo de Banco de Dados MDD (`tools/mdd-client/src/mdd_client/db.py`)
1. **Engine SQLite3 Nativa (`SQLiteMDDDriver`)**:
   - Banco embutido padrão em `<repo>/memory/.mdd.sqlite` (com `PRAGMA journal_mode=WAL;`, `PRAGMA synchronous=NORMAL;`, `PRAGMA foreign_keys=ON;`).
   - Adicionar `.mdd.sqlite`, `.mdd.sqlite-wal` e `.mdd.sqlite-shm` ao `.gitignore`.
2. **Schema Unificado (`mdd_memories`, `mdd_memories_fts`, `mdd_memory_links`)**:
   - `mdd_memories`:
     - `id` (`INTEGER PRIMARY KEY AUTOINCREMENT`)
     - `workspace_slug` (`TEXT NOT NULL DEFAULT 'default'`)
     - `target` (`TEXT NOT NULL DEFAULT 'global'`) — ex.: `global`, `video-factory`, `ai-agents`, `core`
     - `layer` (`TEXT NOT NULL`) — `normative`, `procedural`, `episodic`, `raw`
     - `doc_id` (`TEXT NOT NULL`) — ex.: `DEC-136`, `REQ-079`, `BATCH-081`, `ARCH-017`
     - `slug` (`TEXT NOT NULL`)
     - `title` (`TEXT NOT NULL`)
     - `summary` (`TEXT`)
     - `content` (`TEXT NOT NULL`)
     - `frontmatter_json` (`TEXT`)
     - `tags` (`TEXT`)
     - `source_path` (`TEXT`)
     - `checksum_sha256` (`TEXT NOT NULL`)
     - `status` (`TEXT NOT NULL DEFAULT 'A'`)
     - `updated_at` (`TEXT NOT NULL`)
     - `UNIQUE(workspace_slug, target, doc_id)`
   - `mdd_memories_fts` (`VIRTUAL TABLE USING fts5`):
     - Indexa `doc_id`, `title`, `summary`, `content`, `tags` com `tokenize='unicode61 remove_diacritics 2'` e triggers (`AFTER INSERT`, `AFTER UPDATE`, `AFTER DELETE`) para manter o índice BM25 100% sincronizado automaticamente.
   - `mdd_memory_links`:
     - `id` (`INTEGER PRIMARY KEY AUTOINCREMENT`)
     - `workspace_slug` (`TEXT NOT NULL DEFAULT 'default'`)
     - `source_doc_id` (`TEXT NOT NULL`)
     - `target_doc_id` (`TEXT NOT NULL`)
     - `relation_type` (`TEXT NOT NULL`) — `implements`, `depends_on`, `supersedes`, `references`, `blocks`
     - `UNIQUE(workspace_slug, source_doc_id, target_doc_id, relation_type)`

### 2.2. Sincronizador Bidirecional Markdown ↔ SQLite (`mdd db sync`)
- Varre `memory/` do repositório alvo:
  - Classifica automaticamente a camada (`layer`):
    - `00-*`, `01-*`, `02-*`, `decisions/` ➔ `normative`
    - `03-*`, `04-*`, `.gemini/skills/` ➔ `procedural`
    - `human-requests/`, `implementation/`, `human-reviews/`, `backlog/`, `validation/` ➔ `episodic`
    - `raw/` ➔ `raw`
  - Extrai o frontmatter YAML, `doc_id`, `title`, `summary` e links cruzados (`batch`, `backlog_origin`, links Markdown `[REQ-XXX](...)`) populando `mdd_memories` e `mdd_memory_links`.
  - Usa `checksum_sha256` para atualizar apenas arquivos modificados (execução incremental em `< 200 ms`).

### 2.3. Subcomandos CLI (`mdd db ...` em `tools/mdd-client/src/mdd_client/cli.py`)
- `mdd db sync [--workspace <path>] [--include-skills]`
- `mdd db query "<query>" [--layer <layer>] [--target <target>] [--limit 10] [--json]`: busca FTS5 com ranking BM25 + filtros B-Tree.
- `mdd db graph <DOC_ID> [--json]`: retorna todas as conexões de entrada e saída (`mdd_memory_links`) daquele documento.
- `mdd db learn --layer <layer> --target <target> --doc-id <id> --title "<titulo>" --summary "<resumo>" --content "<conteudo>" [--write-md]`: insere/atualiza aprendizado estruturado no banco e opcionalmente gera/atualiza o `.md`.
- `mdd db export [--output <path.jsonl>] [--target <target>]` e `mdd db import <path.jsonl>`: exporta e importa memórias em formato JSONL 100% compatível com a tabela `ai_memories` do Gestor (`conn2flow-site`).
