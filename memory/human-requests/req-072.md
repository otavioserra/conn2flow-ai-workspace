## 📂 2. Escopo Técnico da Entrega

### 2.1 Especificação do Cabeçalho e Regra de Fallback (Trava 1)
1. **Padrão YAML Frontmatter**:
   Todo documento de governança gerado a partir desta requisição DEVE iniciar com:
   ```markdown
   ---
   id: <ID-CANONICO>
   title: <TITULO-DO-DOCUMENTO>
   status: <STATUS>
   date: <YYYY-MM-DD>
   author: <architect|executor|reviewer|human>
   target_repo: <conn2flow-ai-workspace|outro>
   summary_short: <RESUMO-EM-UMA-LINHA-30-A-140-CHARS>
   summary_medium: <RESUMO-EXPANDIDO-2-A-3-LINHAS>
   ---
   ```
2. **Parser com Fallback Gracioso**:
   Tanto a implementação em PHP quanto em Python devem implementar a seguinte lógica determinística de extração:
   - Se o arquivo começa com `---`, extrair os metadados do bloco YAML delimitador. Usar `summary_short` diretamente na tabela do `index.md`.
   - Se o arquivo **não** começa com `---` (arquivo legado):
     - Localizar a primeira linha iniciando com `# ` e extrair o título.
     - Extrair o ID a partir do nome do arquivo ou do padrão `# ID — Título`.
     - Localizar o primeiro parágrafo de texto corrido não-vazio, limpar quebras de linha e truncar em até 120 caracteres, adicionando reticências se necessário.
     - Identificar o status caso exista linha `* **Status**: ...` ou similar; caso contrário, assumir `indexed` ou `archived`.
   - **Resultado**: Qualquer diretório de memória pode ter seu `index.md` completamente regenerado em milissegundos sem quebrar nenhum arquivo histórico.

### 2.2 Implementação das Rotinas de Indexação e Mutação via CLI
1. **No Core PHP (`conn2flow/cli`)**:
   - Adicionar comando `memory:index` em `cli/c2f.php`:
     - Assinatura: `php cli/c2f.php memory:index [subpasta]`.
     - Quando omitida a subpasta, varre todas as subpastas canônicas de `memory/` que possuem `index.md`.
   - Adicionar comando `memory:set` (Mutação Rápida):
     - Assinatura: `php cli/c2f.php memory:set <alvo> --<campo>=<valor>` (ex: `c2f memory:set req-072 --status=IN-PROGRESS`).
     - Altera ou insere o campo no cabeçalho frontmatter do arquivo alvo e **re-sincroniza o `index.md` local automaticamente**, eliminando edição manual e erros de tabela.
   - Adicionar comando `memory:get`:
     - Assinatura: `php cli/c2f.php memory:get <alvo> [campo]` (retorna o valor ou JSON de metadados).
2. **No Python MDD (`tools/mdd-client` e `tools/mdd-hub`)**:
   - Adicionar comando `mdd index [target_path]` no CLI `mdd`.
   - Adicionar comando `mdd meta set <alvo> <campo> <valor>` e `mdd meta get <alvo> [campo]`.
   - Fornecer API interna em `mdd_client.core.indexer` reutilizável pelo daemon e pelo watcher.
> [!IMPORTANT]
> **Paridade Mandatória Core PHP & Workspace Python**:
> A suíte de comandos de indexação e mutação de memória deve existir com paridade completa de recursos em duas linguagens/ambientes:
> 1. **Core do Sistema (PHP)**: Em `conn2flow/cli/src/Commands/` (`MemoryIndexCommand.php`, `MemorySetCommand.php`, `MemoryGetCommand.php`), acessíveis via `./c2f memory:index`, `./c2f memory:set` e `./c2f memory:get`.
> 2. **Workspace Matriz (Python 3.11+)**: Em `tools/mdd-client/src/mdd_client/` (`cli.py`, `core/indexer.py`), acessíveis via `mdd index`, `mdd meta set` e `mdd meta get`.
> Ambas as implementações devem produzir exatamente a mesma formatação tabular, os mesmos cabeçalhos YAML e a mesma tolerância no fallback gracioso.

### 2.3 Matriz de Handoffs Adaptáveis (Trava 2)
1. Documentar na skill e nas políticas a matriz de despacho de tarefas:
   - **`solo`**: O executor executa e faz auto-revisão contra o checklist.
   - **`dupla`**: O executor conclui o lote e devolve o handoff diretamente para o Macro-Arquiteto com o resumo executivo e comando de continuidade.
   - **`triade`**: O executor emite o recibo do lote (`completions/<batch-id>-receipt.json`) e aciona o Revisor Independente para validação técnica. O Revisor emite `rev-XXX.md` em `memory/human-reviews/`.
2. **Autonomia Supervisionada**:
   - No modo `supervisionado`, qualquer transição de papel aguarda explicitamente o input humano.
   - O prompt gerado para o operador humano deve indicar o próximo agente a ser acionado e incluir o caminho absoluto da raiz do repositório.
