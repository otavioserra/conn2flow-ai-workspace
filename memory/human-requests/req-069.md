## 🎯 1. Objetivo & Contexto

O ecossistema **Memory-Driven Development (MDD)** do Conn2Flow necessita de ferramental automatizado nativo para garantir escalabilidade, independência de IDE e auto-evolução contínua. 

Atualmente, tarefas como inicialização de pastas de memória em novos projetos, compactação preventiva (Regra dos 10 e teto de 50 KB), sincronização de skills e acompanhamento de novidades nos modelos de IA dependem de intervenção manual ou scripts parciais.

Esta requisição formaliza e implementa as duas aplicações canônicas em **Python 3.11+** no repositório matriz (`conn2flow-ai-workspace`):
1. **MDD Client CLI & Daemon** (`ARCH-010`): Ferramenta universal de terminal e background para gerenciamento local de memória em qualquer tipo de projeto.
2. **MDD Hub & Documentation Watcher** (`ARCH-011`): Servidor central e motor de auto-evolução inteligente que rastreia atualizações externas das principais IAs (Gemini, Claude, Codex, Kimi, Cursor) e ingere relatórios de clientes.

Ambas as aplicações serão posteriormente consumidas pela extensão oficial do VS Code (`ARCH-014`).

## 📋 3. Escopo Técnico da Entrega

### 3.1 Componente 1: MDD Client CLI & Daemon (`tools/mdd-client/`)
Desenvolvido em **Python 3.11+** com **Typer** e **Rich**:
1. **Comando `mdd init [caminho] [--type <software|mobile|general>]`**:
   - Injeta a estrutura completa de `memory/` em qualquer pasta ou projeto alvo.
   - Cria a Tríade Fundamental (`00-baseline-architecture.md`, `01-general-memory.md`, `02-policy.md`).
   - Provisiona todos os `index.md` hierárquicos e subpastas (`archive/compacted/`, `archive/original/`, `reports/`, `raw/`).
   - Opcionalmente injeta os kits de agentes canônicos (`.gemini/`, `.claude/`, `.cursor/`, etc.).
2. **Comando `mdd sync`**:
   - Sincroniza deterministicamente as 44 skills e regras locais a partir da matriz canônica.
   - Preserva skills e configurações locais exclusivas.
3. **Comando `mdd compact`**:
   - Audita todos os arquivos ativos de governança no projeto.
   - Aplica a **Regra dos 10 Ativos** (`human-requests/`, `implementation/`, `decisions/`, `reports/`).
   - Aplica o **Teto Preventivo de 50 KB**, gerando resumos em `archive/compacted/` e movendo originais para `archive/original/`.
   - Atualiza automaticamente os arquivos `index.md` correspondentes.
4. **Comando `mdd status`**:
   - Renderiza via Rich um painel visual no terminal com métricas de saúde da memória, arquivos próximos ao teto e status de conformidade.
5. **Comando `mdd report`**:
   - Coleta métricas de atrito, logs de execução e compila relatórios em `memory/reports/`.
   - Opcionalmente despacha o relatório via API REST para o MDD Hub local ou remoto.
6. **Daemon em Background (`mdd daemon` / `mdd watch`)**:
   - Serviço leve assíncrono para vigilância contínua do diretório de memória e alertas de poda.

### 3.2 Componente 2: MDD Hub & Documentation Watcher (`tools/mdd-hub/`)
Desenvolvido em **Python 3.11+** com **FastAPI** / **Uvicorn** / **AsyncIO**:
1. **Hub API Server**:
   - Endpoint de ingestão de relatórios (`POST /api/v1/reports`) enviados pelos MDD Clients locais.
   - Endpoint de telemetria e status do ecossistema (`GET /api/v1/status`).
   - Persistência e consolidação de lições aprendidas em `memory/reports/`.
2. **Documentation Watcher (Scraper de Conhecimento de IA)**:
   - Módulo assíncrono que monitora fontes externas de referência e SDKs:
     - Google Gemini & Google Antigravity (documentação oficial, novos hooks, slash commands).
     - Anthropic Claude Code & MCP SDK (novas flags, tools e patterns).
     - OpenAI Codex / GPT-5 (convenções de projeto e agentes).
     - Moonshot Kimi / Cursor IDE (regras `.cursorrules` e MCP).
   - Extração estruturada de mudanças (novas flags de CLI, novas armadilhas de shell, novos parâmetros).
3. **Três Modos Canônicos de Autonomia de Auto-Evolução**:
   - **`headless` (`totalmente_autonomo`)**: Gera branch Git dedicada (ex: `auto/docs-update-YYYYMMDD`), cria commit atômico e prepara PR sem bloqueios.
   - **`monitored` (`autonomo_com_report`)**: Executa a atualização da documentação/skills e gera relatório executivo imediato em `memory/reports/`.
   - **`reviewer` (`supervisionado`)**: Enfileira as novidades detectadas em `memory/raw/inbox/` aguardando homologação do Engenheiro Chefe.
