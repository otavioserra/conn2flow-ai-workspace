## 📋 3. Protocolo de Transição Mandatório por Repositório

Para **CADA UM** dos 7 repositórios listados, o Executor deve cumprir rigorosamente as seguintes etapas:

### 3.1 Renomeação Git Segura da Pasta de Governança
1. Executar no terminal do repositório alvo:
   ```bash
   git mv sdd memory
   ```
2. Garantir que todo o histórico anterior de requisições, decisões e validações seja preservado sem perdas.

### 3.2 Injeção da Tríade Fundamental MDD na Raiz de `memory/`
Copiar e adaptar a partir de `conn2flow-ai-workspace/memory/`:
1. `memory/00-baseline-architecture.md`: Contextualizado para o papel específico do repositório satélite.
2. `memory/01-general-memory.md`: Mecânica de memória, ciclo de retenção e navegação econômica de tokens.
3. `memory/02-policy.md`: Políticas de governança, Regra dos 10 Ativos e teto de 50 KB.

### 3.3 Provisionamento da Árvore Hierárquica de `index.md` e Pastas Canônicas
1. Em cada subpasta existente de `memory/` (`human-requests/`, `implementation/`, `decisions/`, `backlog/`, `validation/`, etc.), garantir a existência de um `index.md` padronizado.
2. Provisionar pastas `archive/compacted/` e `archive/original/` nos diretórios de arquivamento.
3. Criar a nova pasta `memory/reports/` com seu `index.md`.
4. Criar a pasta `memory/raw/` (com `active/` e `archive/`) com seus `index.md`.

### 3.4 Sincronização das 44 Skills Canônicas
1. Atualizar os kits de agentes locais presentes no repositório (`.claude/skills/`, `.gemini/skills/`, `.cursor/skills/`, `.codex/skills/`, `.github/skills/`) com o acervo canônico completo de 44 skills a partir do `conn2flow-ai-workspace`.
2. Assegurar que as skills locais/privadas existentes no repositório (ex: no `lumix`, `conn2flow-site`, `transformamp`) sejam estritamente preservadas.
3. No Core (`conn2flow`), rodar `php cli/c2f.php ai:sync` e verificar conformidade.

### 3.5 Atualização de Referências de Caminho nos Arquivos de Instrução
Atualizar referências de `sdd/` para `memory/` e menções a SDD para MDD em:
- `AGENTS.md`
- `GEMINI.md`
- `CLAUDE.md` (se presente)
- `.cursorrules` / `.cursor/` (se presente)
- `.codex/` (se presente)
- `README.md` (se referenciar a governança)

### 3.6 Auditoria, Commit Atômico e Push
1. Executar testes de validação rápidos (ex: testes de CLI, compilação de recursos ou testes de extensão quando aplicável).
2. **REGRA INVIOLÁVEL**: Proibido `git add .` ou `git add -A`. Listar arquivos e pastas específicos:
   ```bash
   git add memory/ .gemini/ .claude/ AGENTS.md GEMINI.md ...
   ```
3. Mensagem de commit padronizada:
   ```bash
   git commit -m "docs(memory): migrar SDD para MDD e sincronizar 44 skills canonicas"
   ```
4. Enviar para o repositório remoto:
   ```bash
   git push origin <branch-ativa>
   ```
