#### 1.1 `c2f-project-pipeline-and-tasks/SKILL.md`
Inserir uma subseção concisa (alvo: ~20–24 linhas para preservar folga no teto de 300 linhas) logo após o bloco **Pipeline padrão para projetos (`./c2f project:deploy <projectID>`)** intitulada **"Regra de `dist/`, `css:rebuild` e `assets:publish` por Modo de Deploy (Lab/SSH vs HTTP-Only)"**, cobrindo explicitamente:
- **Destino Local (`local: true`) ou Remoto com SSH (`deploy_mode="ssh"` + `ssh_public_path`):** `c2f css:rebuild --project=<id>` e `c2f assets:publish --project=<id>` aplicam-se normalmente quando necessários (ou via `project:update-all` quando houver mudança do Core).
- **Destino Remoto HTTP-Only (`local: false`, sem SSH — `project:deploy <id>` via `/_api/project/update`):**
  - **Proibido** exigir ou rodar `c2f css:rebuild --project=<id>` ou `c2f assets:publish --project=<id>` contra o servidor remoto (ambos exigem `.env` local ou `ssh_public_path` e falham em HTTP-only).
  - Derivados (`*.precompiled.css`, `*.min.js`) são compilados/minificados localmente antes (quando houver mudança de Categoria C ou JS) e empacotados no ZIP do `project:deploy`.
  - No servidor destino, a ressincronização de `public_html/dist/` ocorre dentro do próprio `/_api/project/update` (sem CLI online nem SSH), retornando o resumo no campo JSON `installation.dist` (`criado`, `verificados`, `publicados`, `atualizados`, `inalterados`, `falhas` a partir da `REQ-306` do Core, que passou a criar e atualizar `dist/` via biblioteca PHP base).
- **Interpretação Determinística de `dist/.manifest.json`:**
  - **`HTTP 404` (ausente — servidores anteriores à `REQ-306` sem `dist/` inicializado):** **NUNCA classificar como bloqueio ou risco de JS antigo.** Quando `dist/.manifest.json` não existe, o runtime faz fallback determinístico para o controlador `arquivo-estatico`, servindo diretamente os arquivos novos de `gestor/` entregues pelo `project:deploy`.
  - **`HTTP 200` (presente — Labs, destinos SSH ou servidores com `REQ-306`):** a entrega estática via `dist/` está ativa; valide que o hash (`sha1`)/versão do asset alterado foi atualizado no manifesto (ou na resposta HTTP efetiva) e confira `installation.dist` na resposta da API.
