# REQ-078 — Internacionalização Completa das 45 Skills, Nova Skill de Governança Multilíngue e Sistema de Detecção de Drift de Tradução (Hash Tracking)

## 📋 Contexto & Diagnóstico

Durante inspeção manual dos templates bilíngues em [`templates/en/`](../../templates/en/) pelo Operador Humano, constatou-se que embora os arquivos estruturais mestres (`CLAUDE.md`, `README.md`, `00-baseline-architecture.md`, etc.) estejam em inglês, **42 das 45 skills canônicas nos kits em inglês permanecem no idioma original (Português)**. Apenas 3 skills foram historicamente traduzidas como prova de conceito (`c2f-environment-configuration`, `project-validation` e `mdd-memory-gardening`).

Quando um desenvolvedor ou agente instala um template com `-Language "en"`, ele recebe 42 skills em português porque os instaladores copiam estaticamente os diretórios de template sem tradução dinâmica em tempo de execução.

Além disso, identificou-se um gargalo de sustentabilidade arquitetural:
1. **Ausência de detecção de descompasso (Translation Drift)**: O arquivo atual [`scripts/skills/translated.json`](../../scripts/skills/translated.json) é uma lista plana de strings (`{"en": ["skill-a"]}`). Quando a skill canônica em português sofre alterações técnicas ou correções no core, o sincronizador protege o arquivo em inglês de ser sobrescrito, mas **não gera nenhum alerta nem métrica de defasagem**. As traduções tornam-se silenciosamente desatualizadas em relação à matriz PT-BR.
2. **Ausência de protocolo canônico para agentes**: Não há uma skill específica que instrua os agentes executores sobre como gerenciar, auditar ou atualizar traduções de skills ao introduzir mudanças na matriz ou adicionar novos idiomas (ex: espanhol no futuro).

## 🎯 Escopo & Objetivos (BATCH-080)

### 1. Tradução Integral das 42 Skills Restantes em `templates/en`
- Traduzir com fidelidade técnica e semântica os 42 arquivos `SKILL.md` restantes para o idioma inglês nos kits de templates (`templates/en/templates/spec-driven-project-*-kit/`).
- Manter estritamente os metadados YAML frontmatter (`name`, `description`, `user-invocable: false`), as seções de gatilhos obrigatórios (`MANDATORY TRIGGER`), regras invioláveis e alertas GitHub-style.
- Cadastrar as 42 skills no registro de traduções oficiais.

### 2. Mecanismo Antidrift de Tradução (Hash & Version Pairing)
- Evoluir [`scripts/skills/translated.json`](../../scripts/skills/translated.json) para uma estrutura com rastreamento de integridade da matriz de origem:
  ```json
  {
    "en": {
      "c2f-database-operations": {
        "source_sha256": "4f53cda18c2baa0c0354bb5f9a3ecbe5ed12ab4d8e11ba873c2f11161202b945",
        "translated_at": "2026-11-05",
        "translator": "mdd-agent"
      }
    }
  }
  ```
- Atualizar [`scripts/skills/sync-skills.cjs`](../../scripts/skills/sync-skills.cjs) e o `mdd sync --audit` (Python):
  - Ao rodar a auditoria sem flags, comparar o hash atual da matriz canônica (`.gemini/skills/<skill>/SKILL.md`) com o `source_sha256` registrado no `translated.json`.
  - Se os hashes forem idênticos: status `PASS` (tradução perfeitamente alinhada).
  - Se a matriz mudou: status `DRIFT_WARNING` destacando com clareza:
    `[DRIFT-WARNING] Skill 'c2f-database-operations' em 'en' está desatualizada em relação à matriz PT-BR (alterada na matriz).`
  - Criar flag de apoio no script (ex: `--update-translation-hash <skill> <idioma>`) para atualizar o hash após a revisão da tradução.

### 3. Nova 46ª Skill Canônica: `c2f-multilingual-skills-governance`
- Criar a nova skill canônica de governança em [`.gemini/skills/c2f-multilingual-skills-governance/SKILL.md`](../../.gemini/skills/c2f-multilingual-skills-governance/SKILL.md) e propagar para todos os 5 kits canônicos (`.claude/`, `.cursor/`, `.codex/`, `.github/`).
- **Gatilho da Skill**: Leitura obrigatória sempre que uma skill for criada, renomeada, editada ou quando um novo idioma de template for adicionado ao ecossistema.
- **Conteúdo Normativo**:
  * Como opera a Tríade Multilíngue (Matriz Canônica PT-BR ➔ Templates Traduzidos ➔ Satélites).
  * O papel do `translated.json` e o fluxo de Hash Pairing.
  * O protocolo de tratamento de Drift: ao modificar uma skill canônica, o agente DEVE verificar se ela possui traduções ativas e registrar a pendência de atualização ou atualizar a versão em inglês imediatamente caso o escopo do lote permita.
  * Procedimento padronizado para expansão para novos idiomas (espanhol, etc.).

### 4. Ajuste dos Validadores, Testes e Extensão
- Atualizar a trava canônica de `sync-skills.cjs` de 45 para **46 skills oficiais**.
- Atualizar a suíte de testes em Python (`tools/mdd-client/tests/test_sync.py`) e testes de customizações/skills para validar as 46 skills canônicas.
- Assegurar regressão zero nas suítes automatizadas (Python 131/131 PASS, Extensão VS Code 133/133 PASS).

## 🛡️ Regras Invioláveis de Execução

1. **Fidelidade Conceitual de Código e Contratos**: Nomes de variáveis globais (`$_CONFIG`, `$_GESTOR`), funções de banco (`banco_select`), constantes e comandos CLI (`c2f`) NÃO devem ser traduzidos. Somente as explicações conceituais, gatilhos e instruções devem ser convertidas para o inglês idiomático.
2. **Proibição de `git add -A` ou `git add .`**: Commits com arquivos específicos listados explicitamente.
3. **Imutabilidade sem Registro**: Nenhuma skill em template de língua estrangeira pode existir sem seu correspondente hash e entrada formal em `translated.json`.
4. **Alerta Não-Bloqueante de Drift**: O descompasso de tradução deve emitir warnings evidentes na auditoria, mas não deve travar deploys de produção ou builds que não toquem em skills.
