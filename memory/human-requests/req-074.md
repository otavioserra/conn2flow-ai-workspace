## 🎯 1. Visão Geral & Objetivos Estratégicos

Com a consolidação da branch `main` e a fundação do ecossistema **Memory-Driven Development (MDD)**, este lote executa três frentes coordenadas:

1. **Desacoplamento do Protocolo MCP para o CLI/Daemon Python (`tools/mdd-client/`)**:
   - O VS Code não deve ser o hospedeiro proprietário de servidores MCP nem deter regras de negócio de memória. O VS Code é estritamente uma **ponte visual (UI Bridge)**.
   - O cliente agnóstico oficial (`mdd`) deve hospedar o servidor MCP oficial em Python, permitindo que qualquer IDE (VS Code, Cursor, Windsurf, Antigravity, Claude Code ou futuros dashboards web) se conecte às ferramentas do MDD via padrão aberto Model Context Protocol (MCP).
   - O comando `mdd daemon` ganha capacidade de iniciar o serviço em segundo plano com o servidor MCP embutido (`mdd daemon --mcp`) ou sob demanda via `mdd mcp`.

2. **Evolução da Extensão VS Code (`vscode-extension/`)**:
   - Transição visual completa dos rótulos e comandos legados de **SDD** para **MDD** (ex: `MDD Explorer`, descoberta prioritária da pasta `memory/` com fallback retrocompatível suave para `sdd/`).
   - Refinamento do **Painel de Choques de Entrega**: fornecer explicações claras do motivo do choque, ação para *"Marcar como Customização Intencional"* e integração direta com o motor de integridade hash do `mdd sync`.

3. **Migração Estrutural de Governança do `conn2flow-home`**:
   - Migrar a pasta de governança de `sdd/` para `memory/` no repositório `conn2flow-home`.
   - Padronizar as memórias raiz para o padrão canônico em inglês (`03-memory-engineering-chief.md` e `04-memory-engineering-execution.md`), criando a estrutura `raw/` e `human-reviews/`.
   - Preservar integralmente todas as especificações e contratos locais (`SPEC.md`, dual-GPU, Caddy `*.conn2flow.local`, portas e rotas).
   - Executar a auto-cura de índices via `mdd index`.
