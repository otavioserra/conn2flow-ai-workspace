## 📋 Escopo do Lote (`BATCH-091`)

### 1. CLI `mdd feedback` e Inbox Federada (`tools/mdd-client/`)
- Criar a área de inbox **`memory/inbox/feedback/`** na matriz (com `README.md` e `index.md`), registrando arquivos atômicos `FB-XXX-<slug>.md` com YAML frontmatter canônico (`id`, `status`, `verdict`, `date`, `repo`, `request`, `batch`, `persona`, `skill`, `kind`, `severity`, `scope`, `evidence`, `summary_short`, `github_issue`).
- Implementar o grupo de comandos **`mdd feedback`** no `mdd-client`:
  1. **`mdd feedback submit`**:
     - Flags: `--repo`, `--req`, `--batch`, `--persona` (`architect|executor|reviewer|curator|optimizer`), `--skill`, `--kind` (`gap|bug|bloat|proposal|learning`), `--severity` (`high|medium|low`), `--scope` (`global|local`, padrão `global`), `--evidence`, `--summary`, `--proposal`, `--matrix <caminho>` (resolve automaticamente a matriz local quando disponível), `--github` (opcional: cria Issue no GitHub com label `skill-feedback` via `gh` CLI com runner injetável), `--json`.
     - Gera o próximo ID livre (`FB-001`, `FB-002`, ...), grava `FB-XXX-<slug>.md` na inbox, atualiza `memory/inbox/feedback/index.md` e indexa no banco SQLite/FTS5 do `mdd-client` quando presente.
  2. **`mdd feedback list`**:
     - Lista feedbacks da inbox com filtros (`--status`, `--verdict`, `--skill`, `--repo`, `--severity`, `--include-github`, `--json`), exibindo tabela legível ou JSON estruturado.
  3. **`mdd feedback triage <id>`**:
     - Aplica um veredito do Tribunal de 4 Filtros (`ACCEPT`, `NEEDS_EVIDENCE`, `QUARANTINE`, `REJECT`, `LOCAL_ONLY`), grava `--reason` e `--reviewer`/`--date` no arquivo `FB-XXX`, atualiza `index.md` e retorna `--json` opcional.
- Cobrir tudo com testes unitários determinísticos em `tools/mdd-client/tests/` (incluindo criação sequencial de IDs, filtros, triage, e backend GitHub Issues via mock/runner injetável sem chamadas de rede).

### 2. Tools MCP no `conn2flow-hub` (`mcp-hub/`)
- Expor no servidor MCP **`conn2flow-hub`** (verificando a estrutura atual do servidor em `mcp-hub/` e mantendo compatibilidade total com as tools existentes):
  - **`submit_skill_feedback`**: recebe os campos estruturados do feedback e delega ao `mdd feedback submit --json` (ou módulo equivalente), retornando o ID `FB-XXX` e caminho gravado.
  - **`list_skill_feedback`**: lista os feedbacks filtrados (`status`, `verdict`, `skill`, `repo`) em JSON para consulta direta pelo `c2f-persona-curator` e por painéis futuros.
- Validar com testes locais do `mcp-hub` / `pytest` (sem exigir rede).
