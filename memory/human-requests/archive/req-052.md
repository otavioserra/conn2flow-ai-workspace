## 1. Justificativa e Objetivos de Negócio

Durante o uso prático da extensão e testes em projetos com máquinas virtuais (HestiaCP), foram identificadas oportunidades críticas de melhoria de usabilidade e integração:
1. **Falha em `c2f css:audit` para Projetos VM**: O comando procura o arquivo `.env` no disco local do Windows em vez de delegar via SSH quando `deploy_mode: "ssh"`, falhando com `ERRO: .env do gestor nao encontrado`.
2. **Aviso no Step 6/8 do `project:update-all`**: A extensão dispara `./c2f project:update-all <target>` sem `--confirmar-remoto`, gerando warning de permissão em projetos VM locais.
3. **Excesso de Notificações Pop-up (Toasts)**: Operações de rotina (como copiar prompt do SDD, término de release) geram notificações persistentes que poluem o centro de notificações do VS Code.
4. **Version Bump do VSIX**: A extensão permanece fixada em `1.0.0.vsix`, dificultando a identificação de compilações pelo usuário e gerando retenção de cache pelo VS Code.
5. **Polimorfismo da Barra de Status e Logs da VM**: O botão inferior continua exibindo "Conn2Flow Docker" mesmo quando o projeto ativo opera em VM HestiaCP (onde não há Docker), e faltam atalhos para os logs da VM (`php-error.log`, `nginx-error.log`).
6. **Acervo de Documentações do Core (`ai-workspace/pt-br/docs`)**: A vasta documentação técnica do sistema em `conn2flow/ai-workspace/pt-br/docs` precisa ser exposta no índice e acessível por uma busca interativa rápida na árvore.
7. **Navegação de Links no Preview Markdown**: Clicar em links internos dentro do preview renderizado (MPE) abre abas de código-fonte separadas em vez de navegar mantendo o modo preview contínuo.

## 2. Escopo Técnico da Entrega

### 2.1 Core CLI (`conn2flow/cli/`):
- **SSH no `css:audit`**:
  * Em `CssAuditCommand.php`: resolver se o projeto possui `deploy_mode: "ssh"`.
  * Caso seja SSH, disparar a auditoria remotamente na VM via `SshRemoteTransport` (`ssh user@host "cd <path> && ./c2f css:audit"` ou comando equivalente), exibindo a tabela de diagnóstico sem exigir `.env` local no Windows.
- **Autorização Automática em Projetos VM Locais (`project:update-all`)**:
  * Em `ProjectUpdateAllCommand.php`: se o projeto tiver `local: true` e `deploy_mode: "ssh"`, permitir que a etapa 6/8 (`css:rebuild`) prossiga automaticamente ou repasse a autorização remota sem emitir o warning.
- **Preservação de Manifestos de Build**:
  * Garantir que `.tailwind-build-manifest.json` com os 237 recursos em cache seja versionado e preservado para evitar compilações desnecessárias do zero.

### 2.2 Extensão VS Code (`vscode-extension/`):
- **Saneamento de Notificações Pop-up**:
  * Substituir `vscode.window.showInformationMessage` em ações corriqueiras de sucesso (ex: copiar prompt no SDD, conclusão de tarefas normais) por mensagens na barra de status que expiram automaticamente em 3 segundos (`vscode.window.setStatusBarMessage(..., 3000)`).
  * Reservar pop-ups (`showInformationMessage` / `showErrorMessage`) estritamente para erros, avisos ou confirmações críticas.
  * As notificações de progresso (`withProgress`) devem fechar suavemente sem deixar toasts residuais.
- **Passar `--confirmar-remoto` na Extensão**:
  * Em `extension.ts` nos comandos `conn2flow.projects.updateAllTarget` e `updateAllWithSelect`: verificar se `ProjectsManager.isTargetVm()`; caso positivo, anexar `--confirmar-remoto` à linha de comando.
- **Version Bump Automatizado da Extensão**:
  * Atualizar a versão no `package.json` para `1.1.0`.
  * Adicionar rotina ou script npm para incrementar automaticamente a versão patch ao empacotar (`npm run package`).
- **Barra de Status Inteligente (Docker vs VM) e Logs da VM**:
  * Registrar listeners para `ProjectsManager.onTargetProjectChanged` ou na mudança de configuração, garantindo que `updateStatusBar()` seja reexecutado ao trocar o projeto ativo.
  * Quando o projeto ativo for VM (`isTargetVm()`):
    - Ocultar ou transformar o botão de Docker em `$(vm) Conn2Flow VM` com tooltip indicando o IP e usuário SSH.
    - Na seção Diagnóstico, adicionar comandos para consultar logs da VM via SSH (`tail -n 100` em `php-error.log` e `nginx-error.log` na pasta `logs/` do Gestor remoto).
- **Busca Rápida de Documentações (`ai-workspace/pt-br/docs`)**:
  * Adicionar comando `conn2flow.docs.search` na seção `📚 Documentações & Configurações` abrindo um `vscode.window.showQuickPick` com os tópicos de `ai-workspace/pt-br/docs/` e `docs/`, abrindo o preview do arquivo selecionado.
- **Navegação Contínua no Preview Markdown**:
  * Ao navegar por links em modo `preview`, garantir que o documento de destino permaneça em preview sem abrir abas de código .md redundantes.

## 3. Critérios de Aceite

1. `c2f css:audit --project=conn2flow-site-local` conecta via SSH e exibe o relatório de classes e procedência sem erro de `.env`.
2. O clique em "Atualizar Projeto Alvo" para projetos VM executa a etapa 6/8 com `--confirmar-remoto` sem warnings.
3. Copiar prompt ou concluir comandos normais não gera toasts acumulados no centro de notificações; usa status bar efêmera.
4. O VSIX é gerado com versão `1.1.0` (ou superior) e arquivo `conn2flow-tools-1.1.0.vsix`.
5. A barra de status reflete dinamicamente `Conn2Flow VM` quando o projeto for VM e oferece atalhos para logs remotos.
6. A árvore possui comando de busca rápida para as documentações de `ai-workspace/pt-br/docs`.
7. `npm test` na extensão em 100% verde e testes do Core aprovados.
8. Recibo emitido em `completions/BATCH-054-executor-receipt.json`.
