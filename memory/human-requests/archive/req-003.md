# REQ-003: Governança de Memory Gardening, Destilação de Memórias em Skills e Suporte ao Cursor IDE

## 1. Problema
Esta requisição atende a duas necessidades estratégicas do ecossistema:

1. **Otimização de Contexto (Memory Gardening)**: À medida que os projetos evoluem, os arquivos de **Memória de Engenharia** (`MEMORIA-ENGENHARIA-EXECUCAO.md` e `MEMORIA-ENGENHARIA-CHEFIA.md`) acumulam post-mortems longos, regras de build, correções pontuais de bugs e notas de ambiente. No repositório core `conn2flow`, por exemplo, a memória de execução ultrapassou **150 KB (~300 linhas)**. Isso faz com que cada nova sessão de agente IA consuma entre 35.000 e 40.000 tokens apenas para carregar o histórico de memórias, degradando a janela de contexto, reduzindo a precisão das respostas e elevando os custos de processamento.
2. **Integração com o Cursor IDE (VS Code Agent)**: Atualmente, os kits instaladores atendem apenas ao Claude Code e ao GitHub Copilot. Como o desenvolvimento também está sendo realizado via agente do Cursor IDE no VS Code, precisamos fornecer o **Cursor Kit** oficial (`.cursor/rules/sdd.mdc` e `.cursorrules`) para que o agente do Cursor conheça e respeite a governança SDD.

## 2. Ajustes Requeridos

### A. Diretrizes e Skills Normativas no Workspace (`conn2flow-ai-workspace`)
1. **Documentação Normativa**:
   * Criar `sdd/process/MEMORY-GARDENING-GUIDELINES.md` detalhando as regras de tamanho limite das memórias (~15 KB ou 50 linhas), critérios de gatilho para poda e o procedimento de conversão em Skills.
2. **Skill de Governança (`sdd-memory-gardening`)**:
   * Criar o template da skill `sdd-memory-gardening` em `pt-br/templates/` e `en/templates/` para instruir qualquer agente sobre como realizar o processo de poda de forma padronizada.
3. **Core Skills de Engenharia Conn2Flow**:
   * `c2f-json-resources-sync`: Regra proibindo a edição manual de checksums/versões nos arquivos `.json` de módulos (devem ser deixados vazios, o deploy recalcula automaticamente).
   * `c2f-widget-development`: Padrão de injeção desduplicada de recursos via `gestor_pagina_recursos_incluir()`, contratos AJAX e regex tolerante a `@?\[\[item#var\]\]@?`.
   * `c2f-gd-image-safety`: Manipulação segura de imagens com GD/WebP, verificações com `function_exists` e captura com `\Throwable`.
   * `c2f-database-testing`: Diretrizes para testes isolados com SQLite em memória ou container MySQL dedicado (`conn2flow_test`).
   * `c2f-mysql-utf8-emoji-encoding`: Padrão de codificação JSON `json_encode(..., JSON_UNESCAPED_SLASHES)` (sem `JSON_UNESCAPED_UNICODE`) em conexões MySQL `utf8` 3-bytes.

### B. Criação dos Templates e Scripts do Cursor Kit (`conn2flow-ai-workspace`)
1. **Templates Bilingues do Cursor Kit**:
   * Criar `pt-br/templates/spec-driven-project-cursor-kit/` e `en/templates/spec-driven-project-cursor-kit/`.
   * **`.cursorrules`**: Regras globais de atuação no papel de Executor (Micro-Operador), com restrições de escrita na especificação (`SPEC.md`) e log de decisões (`DECISION-LOG.md`).
   * **`.cursor/rules/sdd.mdc`**: Regra modular em Markdown Cursor com metadados YAML (`globs: ["sdd/**/*"]`) para ativar automaticamente o contexto SDD ao tocar na pasta `sdd/`.
2. **Scripts Instaladores do Cursor Kit**:
   * Criar `scripts/install-spec-driven-cursor-kit.ps1` (PowerShell) e `.sh` (Bash) herdando o suporte a `-TargetRepoPath`, `-Force`, `-AgentPrefix` e `-Language` (pt-br/en), preservando arquivos existentes do usuário e injetando as pastas `archive/`.
