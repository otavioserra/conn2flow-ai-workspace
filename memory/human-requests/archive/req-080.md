# REQ-080 — Saneamento Visual de Choques por Projeto, Editor Isolado de Dados do Projeto (`environment.json` Scoped Editor), Instalação Local do VSIX e Ciclo Iterativo de Homologação da Extensão

## 📋 Contexto & Diagnóstico

Durante a gravação de um vídeo demonstrativo pelo Operador Humano utilizando a extensão **Conn2Flow Dev Tools (`vscode-extension/`)**, foram identificados dois problemas críticos de usabilidade e privacidade na aba **Projetos e Ambientes de Testes** (`section.projects`), além da necessidade de atualizar a instalação local da extensão na janela do VS Code do operador:

1. **Poluição Visual de Pontos de Exclamação (`⚠️ Choques de entregas: <Projeto>`)**:
   - Em [`vscode-extension/src/providers/conn2flowTreeProvider.ts`](../../../vscode-extension/src/providers/conn2flowTreeProvider.ts) (linhas 202–210), a árvore estava iterando sobre `ProjectsManager.getProjectsList()` e renderizando incondicionalmente um item com ícone `warning` (`!`) para **todos os projetos cadastrados** no `environment.json`.
   - Isso gera uma parede de alertas falsos na interface (dando a impressão de erro generalizado durante apresentações/vídeos), destoando do padrão das demais ações da seção (`Deploy`, `Sincronizar Core`, etc.), que exibem a ação direta apenas para o `target` ativo e um item seletor (`Selecionar Projeto...`).
2. **Edição Isolada dos Dados de um Projeto (`devProjects[id]` no `environment.json`)**:
   - O arquivo `C:\Users\otavi\OneDrive\Documentos\GIT\conn2flow\dev-environment\data\environment.json` armazena todos os projetos em `devProjects`, além de chaves globais sensíveis (como `gemini.apiKey` e `api.access_token` de todos os clientes).
   - O operador deseja uma funcionalidade análoga ao botão **"Editar Ações do Projeto"** (`conn2flow.custom.editManifest`), porém **restrita exclusivamente aos dados do projeto selecionado (`devProjects[projectId]`)**: ao clicar, deve abrir apenas o JSON com os campos daquele projeto específico (sem expor na tela os demais projetos nem as chaves globais do `environment.json`), e ao salvar (`Ctrl+S`), o sistema deve validar o JSON, atualizar automaticamente apenas o nó `devProjects[projectId]` dentro do `environment.json` original e atualizar a árvore da extensão (`refresh()`).
3. **Instalação Imediata da Versão Corrigida no VS Code Local e Bateria de Testes Iterativos**:
   - O pacote `.vsix` gerado nos lotes anteriores (`BATCH-076`) não havia sido instalado na janela principal do VS Code do operador. O agente deve compilar, empacotar e instalar o `.vsix` localmente (`code --install-extension ... --force`) e permanecer disponível nesta mesma requisição (`REQ-080` / `BATCH-082`) para corrigir iterativamente quaisquer defeitos adicionais apontados pelo operador durante seus testes ao vivo.

## 🎯 Escopo & Objetivos (`BATCH-082`)

### 1. Saneamento de "Choques de Entregas" na Aba Projetos e Ambientes de Testes
- Em [`vscode-extension/src/providers/conn2flowTreeProvider.ts`](../../../vscode-extension/src/providers/conn2flowTreeProvider.ts):
  - Remover o `.map()` que despeja todos os projetos de `ProjectsManager.getProjectsList()` com ícone `warning` na árvore.
  - Dentro do bloco `if (target)` (junto às ações do projeto ativo), exibir apenas **1 item para o projeto alvo ativo**:
    - `projects.conflictsFor` (`Choques de entregas: {target}` / `Delivery conflicts: {target}`), utilizando ícone neutro de comparação (`diff` ou `git-compare`, sem ponto de exclamação alarmista estático), acionando `conn2flow.projects.listConflicts` com `[target]`.
  - Na lista geral da seção `projects` (junto a `Deploy (Selecionar Projeto...)`), adicionar **1 item seletor**:
    - `projects.conflictsSelectProject` (`Choques de entregas (Selecionar Projeto...)` / `Delivery conflicts (Select Project...)`), acionando `conn2flow.projects.listConflicts` sem argumentos (o `ProjectConflictsManager.openForProject()` já abre o `QuickPick` automaticamente quando `projectId` não é informado).

### 2. Novo Editor Isolado de Dados do Projeto (`Scoped Project Config Editor`)
- Criar em [`vscode-extension/src/providers/projectsManager.ts`](../../../vscode-extension/src/providers/projectsManager.ts) (e registrar em [`extension.ts`](../../../vscode-extension/src/extension.ts), [`conn2flowTreeProvider.ts`](../../../vscode-extension/src/providers/conn2flowTreeProvider.ts), [`localizationCatalog.ts`](../../../vscode-extension/src/localizationCatalog.ts), `package.json`, `package.nls.json` e `package.nls.pt-br.json`):
  - Comandos:
    - `conn2flow.projects.editTargetConfig`: **Editar Dados do Projeto: {target}** (visível quando há um `target` ativo, ícone `edit` ou `settings-gear`).
    - `conn2flow.projects.editProjectConfigSelect`: **Editar Dados de Projeto (Selecionar...)** (abre `QuickPick` para escolher qual projeto editar).
- **Mecânica de Isolamento e Sincronização Automática ao Salvar (`Ctrl+S`)**:
  - Ao acionar a edição de um `projectId`:
    1. Ler `environment.json` via `ProjectsManager.getEnvironmentFilePath()` e extrair **somente** o objeto `data.devProjects[projectId]`.
    2. Gerar/abrir um arquivo JSON provisório isolado (ex.: em diretório temporário seguro ou `.c2f/temp-project-<projectId>.json` fora do stage Git / `os.tmpdir()`) contendo exclusivamente o JSON formatado (`JSON.stringify(projectData, null, 2)`) daquele projeto.
    3. Monitorar o evento `vscode.workspace.onDidSaveTextDocument` para esse arquivo provisório:
       - Sempre que o operador salvar (`Ctrl+S`), fazer o parse do JSON editado.
       - Se o JSON for inválido, exibir `vscode.window.showErrorMessage` claro sem corromper o `environment.json`.
       - Se o JSON for válido, releia o `environment.json` completo do disco, substitua **exclusivamente** `data.devProjects[projectId]` pelo objeto salvo (preservando `name`, `devEnvironment`, `gemini` e todos os outros projetos de `devProjects` intactos), grave no `environment.json` com indentação de 2 espaços, emita feedback na barra de status/notificação e chame `treeProvider.refresh()`.
    4. Ao fechar a aba do arquivo provisório (`onDidCloseTextDocument`), limpar/remover o arquivo temporário do disco com segurança.

### 3. Compilação, Empacotamento `.vsix` e Instalação Local no VS Code
- Compilar o TypeScript (`npm run compile`), atualizar/rodar a suíte de testes da extensão (`npm test`), gerar o pacote `.vsix` atualizado (`npx @vscode/vsce package`) e instalar diretamente no VS Code local do operador (`code --install-extension <arquivo.vsix> --force`) para que um simples `Reload Window` já carregue a versão nova.

### 4. Suporte ao Ciclo Iterativo de Testes com o Operador Humano
- Manter o lote `BATCH-082` aberto às solicitações diretas do Operador Humano durante a sessão de testes práticos da extensão, aplicando correções imediatas, reempacotando e reinstalando o `.vsix` local a cada ajuste até o aceite final do humano.

## 🛡️ Regras Invioláveis de Execução

1. **Privacidade e Preservação Integral do `environment.json`**: Nunca expor outros projetos ou chaves globais no buffer isolado do projeto, e nunca perder chaves existentes de outros projetos ao salvar de volta no `environment.json`.
2. **Paridade Bilíngue (`PT-BR` / `EN`)**: Todas as novas chaves de interface e tooltips devem ser cadastradas em `localizationCatalog.ts`, `treeTooltipPolicy.ts`, `package.nls.json` e `package.nls.pt-br.json`.
3. **Proibição de `git add -A` ou `git add .`**: Commits (apenas quando autorizados) devem listar caminhos explícitos.
