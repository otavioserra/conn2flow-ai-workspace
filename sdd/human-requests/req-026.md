## 🎯 1. Diagnóstico & Contexto Operacional

Durante o avanço de compilação de CSS no Core (`BATCH-144`), duas necessidades operacionais críticas foram verificadas:

### 1.1. Inclusão do `css:rebuild` como Etapa Final dos Pipelines (Prevenção do Estado Híbrido)
Os pipelines `c2f manager:update-all` e `c2f project:update-all <id>` foram oficialmente atualizados no Core para recalcular o CSS derivado após a sincronização de arquivos e banco de dados:
* **Pipeline do Sistema (4 etapas)**: Core → Resources (`resources:sync`) → Files → Database (Upsert + Migrations) → **CSS Rebuild (`css:rebuild`)**
* **Pipeline de Projetos (6 etapas)**: Core → DB → Resources → Files → DB (Upsert + Migrations) → **CSS Rebuild (`css:rebuild`)**
* **Por que essa etapa é vital**: O `css:rebuild` no encerramento é a etapa mandatória que **impede o estado híbrido (CSS antigo/stale em cache vs novo HTML entregue) de retornar após cada deploy**.

### 1.2. Bug de Paralelismo & Supressão Silenciosa de Warnings PHP (Caso `$fontesExtras`)
Rodar múltiplos comandos pesados de compilação ou banco simultaneamente no mesmo container/ambiente trava o processo do PHP e oculta warnings e notices críticos.
* **Caso Prático Documentado**: Um bug real (`$fontesExtras` sem parâmetro na assinatura do método) permaneceu invisível por horas — as `tailwind_sources` nunca eram aplicadas e nada no terminal indicava o erro, porque o processo rodava em background/com buffer suprimido.
* **Diretriz Mandatória**: Comandos de compilação em lote (`css:rebuild`, `resources:sync`, `project:update-all`, `manager:update-all`, `db:migrate`) DEVEM rodar **estritamente sozinhos (sequenciais)**.
* **Saída Desbufferizada / Foreground**: É expressamente proibido executar esses comandos em background cego ou com redirecionamentos que suprimam `stderr`. A execução em foreground é obrigatória para expor warnings e permitir correções imediatas.
