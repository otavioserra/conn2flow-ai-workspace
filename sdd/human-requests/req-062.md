## 1. Justificativa e Diagnóstico Técnico

A requisição **REQ-061** (`BATCH-063`) introduziu o subsistema completo de resolução visual de choques de entrega na extensão **Conn2Flow Dev Tools (`conn2flow-tools`)**, integrando-se aos novos comandos do CLI do Core (`c2f update:conflicts` e `c2f update:resolve` com `--json`), abrindo diff lado a lado, suportando arquivos de mescla e tratando choques de exclusão e registros de banco de dados (`db:<tabela>?<chave>`).

A suíte de testes unitários foi expandida para **124/124 testes aprovados** com compilação limpa.

Para disponibilizar essas melhorias aos usuários e equipes de desenvolvimento no ecossistema do Visual Studio Code e no **Visual Studio Marketplace (Microsoft)**, é necessário:
1. **Resolver a Incompatibilidade do Toolchain de Empacotamento**: O comando de empacotamento com `@vscode/vsce@latest` falhava no Node.js v20.14.0 devido ao erro `ERR_REQUIRE_ESM` causado por dependências puramente ESM (`parse5`/`cheerio`). O diagnóstico do Macro-Arquiteto comprovou que fixar `@vscode/vsce@2.24.0` resolve perfeitamente a compilação e o empacotamento sem exigir atualização do runtime Node.js da máquina.
2. **Incremento Semântico de Versão**: A versão em `package.json` e `package-lock.json` deve ser promovida de `1.1.1` para `1.1.2`.
3. **Geração do Pacote `.vsix` Oficial**: Gerar e validar o artefato `conn2flow-tools-1.1.2.vsix`.
4. **Atualização do Changelog**: Documentar as entregas do v1.1.2 em `CHANGELOG.md`.
5. **Roteiro de Publicação**: Fornecer as instruções claras para envio no Portal de Gerenciamento do Marketplace (`https://marketplace.visualstudio.com/manage`) e via CLI com PAT.

## 2. Escopo Técnico da Entrega

### 2.1 Ajuste do Toolchain de Empacotamento (`package.json`)
- Atualizar o script de packaging no `vscode-extension/package.json`:
  ```json
  "package": "npm run version:bump && npx --yes @vscode/vsce@2.24.0 package"
  ```
- Garantir que a execução de `npm run package` ou do comando direto do vsce execute sem erros de ESM no Node 20.14.

### 2.2 Bump de Versão e Changelog
- Executar `npm run version:bump` em `vscode-extension/` (promovendo de `1.1.1` para `1.1.2` em `package.json` e `package-lock.json`).
- Atualizar o arquivo `CHANGELOG.md` (ou `vscode-extension/CHANGELOG.md`) com a seção `[1.1.2] - 2026-09-30`:
  - **Novidades**: Árvore interativa de choques de entrega por projeto (`update:conflicts --json`).
  - **Diff e Mescla**: Abertura automática de diff lado a lado (`vscode.diff`) entre versão no ar e nova versão, com suporte a editor de mesclagem e modificador `--local`.
  - **Correções & Robustez**: Suporte a choques de arquivos removidos e choques em registros SQL de tabelas (`db:<tabela>?<chave>`); tolerância a serializações de arrays vazios `[]` do PHP; mensagens amigáveis para erros do CLI `{ok:false, erro}` sem quebrar a árvore.

### 2.3 Compilação, Testes e Geração do VSIX
- Executar `npm test` garantindo **124/124 testes verdes**.
- Gerar o pacote `conn2flow-tools-1.1.2.vsix` na pasta `vscode-extension/`.
- Atestar o tamanho e a integridade estrutural do pacote gerado.

### 2.4 Roteiro de Publicação e Pré-requisitos
- Documentar no relatório de lote `batch-064.md` o procedimento para publicação:
  - **Via Portal Web**: Upload direto do `.vsix` em `https://marketplace.visualstudio.com/manage` sob o publicador `conn2flow`.
  - **Via CLI**: Uso de Personal Access Token (PAT) do Azure DevOps com escopo `Marketplace: Manage`.
- **Pré-requisito do Core (`conn2flow`)**: Instruir o desenvolvedor humano a concluir/estashar o trabalho local pendente no Core para rodar `git pull origin main` no diretório principal `conn2flow`, disponibilizando os novos comandos CLI para a extensão.
