## 🎯 1. Diagnóstico das 5 Ambiguidades

### A. Teto da Memória (10 KB vs 50 KB)
A skill `sdd-memory-gardening` foi calibrada na REQ-015 para 35 KB (alerta) e 50 KB (teto). No entanto, o cabeçalho de `sdd/MEMORIA-ENGENHARIA-EXECUCAO.md` em alguns repositórios ainda continha texto legado ("abaixo de 10 KB/50 linhas"), induzindo agentes a realizar podas prematuras.

### B. Criação de `req-XXX.md` por Agentes Executores
O README histórico dizia que apenas o Arquiteto escreve requisições. No entanto, na operação real, quando o usuário humano dialoga diretamente com o Executor no chat ou quando uma oportunidade técnica é identificada, o Executor PODE criar `req-XXX.md`, desde que siga o protocolo de reserva atômica para não colidir com agentes paralelos.

### C. Hábito de "Pendente do Operador"
Com os comandos `c2f auth:cookie` e `c2f page:inspect`, o agente possui os meios para validar estilos, animações e erros de console sozinho. "Pendente do operador" deve ser a exceção, exigindo justificativa técnica.

### D. Duas Camadas de Memória sem Divisão Clara
Havia sobreposição entre o que deve ser gravado em `sdd/MEMORIA-ENGENHARIA-EXECUCAO.md` (Git) e na memória persistente da ferramenta do agente.

### E. Envelhecimento Silencioso de Memórias
Notas de restrição antigas (ex: "proibido ler .env") permaneciam como dogmas mesmo após a alteração da configuração do repositório.

## 🛠️ 2. Resoluções Normativas & Diretrizes

### 1. Protocolo de Reserva Atômica para Criação de `req-XXX.md`
Qualquer agente (Arquiteto ou Executor) está autorizado a criar `req-XXX.md` quando instruído pelo operador humano ou ao levantar uma necessidade técnica, seguindo estritamente:
1. Executar `git pull origin <branch>` para sincronizar o estado mais recente.
2. Reler atomicamente o diretório `sdd/human-requests/` para identificar o próximo número livre (ex: se o maior for `req-020.md`, o próximo é `req-021.md`).
3. Criar o arquivo `req-XXX.md`, atualizar `sdd/human-requests/CURRENT.md` e **commitar/pushar imediatamente**:
   ```bash
   git add sdd/human-requests/req-XXX.md sdd/human-requests/CURRENT.md
   git commit -m "docs(sdd): reserve REQ-XXX for <título>"
   git push origin <branch>
   ```
   Isso garante que agentes concorrentes em outras worktrees vejam o número reservado e evitem sobrescrita.

### 2. Unificação Universal dos Tetos de Memory Gardening
* Atualizar a linha de política em `sdd/MEMORIA-ENGENHARIA-EXECUCAO.md` (e `ENGINEERING-MEMORY-EXECUTION.md`) em todos os repositórios para:
  `> **Política**: manter 12 a 15 tarefas recentes, alerta preventivo em 35 KB (~100 linhas), teto mandatório de poda em 50 KB (~150 linhas) e alvo pós-poda em ~15 KB. A memória de Chefia é somente leitura.`

### 3. Regra Anti-Hábito de "Pendente do Operador"
* O agente **DEVE OBRIGATORIAMENTE** executar `c2f page:inspect` / `c2f auth:cookie` ou a suíte de testes antes de considerar um item visual/runtime como validado.
* É **proibido** marcar "pendente do operador" por comodidade. Caso uma tela não possa ser inspecionada, o agente deve registrar no checklist a razão técnica exata (ex: dependência de gateway externo de produção sem mock local).

### 4. Divisão das Camadas de Memória
* **`sdd/MEMORIA-ENGENHARIA-EXECUCAO.md` (Repositório / Git Compartilhado)**:
  - Fatos técnicos do software: bugs resolvidos no core, hacks de banco, nuances de compilação/CSS, comandos CLI descobertos e lições aprendidas. Visível a todos os agentes e desenvolvedores.
* **Memória Persistente da Ferramenta de IA (Local / Privada)**:
  - Preferências comportamentais do desenvolvedor (estilo de chat, idioma, atalhos de terminal).

### 5. Princípio da Autoridade do Código e SPEC sobre Memórias
* Toda restrição técnica em memória deve carregar data (`YYYY-MM-DD`).
* As configurações reais dos arquivos (`settings.json`, `.env`, `SPEC.md`, código-fonte) têm **autoridade absoluta** sobre anotações de memórias passadas. Se uma configuração mudar, a memória correspondente deve ser invalidada e alinhada imediatamente.
