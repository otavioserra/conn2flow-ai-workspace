---

## 🏗️ Os 3 Pilares da Implementação

### 1. ⚙️ Pilar 1: Conn2Flow Core CLI (`conn2flow/cli/`)
* **Pasta Raiz**: `conn2flow/cli/` com PHP 8.2+, strict types e arquitetura orientada a objetos (`Contracts/`, `Console/`, `Commands/`).
* **Wrappers Executáveis**: `conn2flow/c2f` (Bash) e `conn2flow/c2f.ps1` (PowerShell).
* **Comandos Mapeados do `tasks.json`**:
  - `c2f resources:sync` ➔ Executa compilação de recursos (`atualizacao-dados-recursos.php`).
  - `c2f ai:sync` ➔ Executa sincronização das 32 skills.
  - `c2f db:update` / `c2f db:test` ➔ Sincronização e testes de banco de dados.
  - `c2f module:create <id>` ➔ Scaffold canônico baseado em `modulos-grupos`.
  - `c2f docker:status` / `c2f docker:logs` / `c2f docker:truncate-logs` ➔ Rotinas de container.

### 2. ⚡ Pilar 2: Servidor MCP Hub Dual-Mode (`conn2flow-ai-workspace/mcp-hub/`)
* **Servidor MCP Local**: Servidor Node.js/TypeScript leve expondo ferramentas MCP para Antigravity, Claude Code e Cursor:
  - `c2f_run_command(command, args)` ➔ Executa qualquer comando do CLI `c2f`.
  - `dispatch_task(repo, req_id, prompt, mode)` ➔ Fila de despacho de tarefas.
  - `report_completion(batch_id, logs)` ➔ Notificação de conclusão de volta ao Arquiteto.
* **Dual-Mode**:
  - *Modo 1 (Supervisionado)*: Carrega o chat no VS Code para acompanhamento visual do código.
  - *Modo 2 (Headless)*: Processamento transparente em background.
* **Container Docker**: `Dockerfile` e `docker-compose.yml` para execução isolada em container `conn2flow-mcp-hub`.

### 3. 🌲 Pilar 3: Git Worktrees & Governança Concorrente (`scripts/git/`)
* Utilitário `scripts/git/create-agent-worktree.ps1` e `.sh` para criar pastas/worktrees isoladas (`worktrees/feat-req-XXX`).
* Permite que múltiplos agentes trabalhem simultaneamente em diferentes módulos sem colisões de branch na árvore principal.
