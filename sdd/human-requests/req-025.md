## 🎯 1. Diagnóstico dos 8 Achados de Engenharia & Causa Raiz

### 1.1. Pipeline ≠ Cópia de Arquivo (`cp`)
Agentes frequentemente tentam sincronizar alterações copiando arquivos manualmente (`cp`) para pastas de espelho (`dev-environment/data/sites/...`). Isso resulta em arquivos divergentes, `*Data.json` não recompilados, migrações Phinx não aplicadas e banco desincronizado.
* **Regra Canônica**: É estritamente proibido sincronizar por cópia manual. O agente DEVE rodar:
  - `c2f manager:update-all` (Core -> Resources -> Files -> Database) para o sistema;
  - `c2f project:update-all <id>` (Core -> DB -> Resources -> Files -> DB) para projetos.

### 1.2. A Flag `local` do `environment.json` como Autoridade Declarativa
Projetos existem em pares (ex: `transformamp` / `transformamp-local`, `snapphoton` / `snapphoton-local`). Comandos de leitura parecem idênticos, mas o destino do deploy e o banco variam.
* **Regra Canônica**: Antes de interagir com qualquer projeto, inspecione `devProjects.<id>.local` no `dev-environment/data/environment.json`:
  - `local: true`: Ambiente de teste local. Liberdade total para alterar, testar, quebrar, fazer deploy e manipular banco.
  - `local: false`: **Ambiente de produção real**. Exige autorização explícita e confirmação do operador humano.

### 1.3. Fonte da Verdade em Runtime
O runtime serve HTML e CSS exclusivamente do **BANCO DE DADOS** (`gestor.php:2782`). O diretório `resources/` é lido diretamente apenas sob `DEVELOPMENT_ENV=true`. Ao investigar o comportamento de uma página publicada, o agente DEVE inspecionar o banco primeiro.

### 1.4. Autoria vs Derivado (Eliminação do Contorno Manual de CSS)
A prática antiga de zerar `paginas.css_compiled = NULL` no banco era um contorno manual de um problema estrutural.
* `html` e `css`: São **AUTORIA** (preservados conforme `user_modified` e `project`).
* `css_precompiled` e `css_compiled`: São **DERIVADOS** (nunca preservados como autoria, sempre recalculáveis a partir da autoria vigente).
* **Novo Procedimento**: Usar `c2f css:rebuild` (e `c2f css:rebuild --url=<rota>`) para recalcular o CSS derivado contra o HTML real do banco.

### 1.5. `tailwind_sources` em PHP/JS é Sintoma de Dívida Técnica
Apontar `tailwind_sources` para arquivos `.php` ou `.js` indica classes utilitárias montadas em tempo de execução via JavaScript ou PHP. Isso viola a arquitetura do Conn2Flow (onde PHP/JS não devem carregar marcação ou estilos). Trate como dívida técnica a eliminar (movendo para componentes/templates).

### 1.6. Novos Instrumentos de Medição de CSS
Em vez de inferir estilização por leitura cega de código:
* `c2f css:audit`: Audita procedência (`css_source_hash`), cobertura e classes embutidas em PHP/JS por tabela.
* `c2f css:audit --url=<rota>`: Audita a página composta real e mapeia classes órfãs ao recurso de origem.
* `c2f css:rebuild --url=<rota>`: Reconstrói o CSS derivado usando o HTML renderizado como fonte adicional.

### 1.7. As 5 Armadilhas do Ambiente Windows / Git Bash / Docker
1. **Conversão de Caminhos no Git Bash**: `docker exec ... /var/www/...` é corrompido para `C:/Program Files/Git/var/www/...`. **Solução**: prefixar com `MSYS_NO_PATHCONV=1`.
2. **`curl` com Caractere `<`**: `-F "campo=<valor"` interpreta `<` como leitura de arquivo local. **Solução**: usar `--form-string`.
3. **Python Heredocs**: Sequências `\b` e `\s` viram bytes de controle dentro do arquivo. **Solução**: usar raw strings (`r"""..."""`) ou `chr(92)`.
4. **Asserts com Falha Silenciosa**: Asserts em scripts intermediários deixam arquivos corrompidos pela metade.
5. **Formulários do Gestor**: São `multipart/form-data` com gatilhos ocultos (`_gestor-atualizar`, `_gestor-registro-id`).

### 1.8. Mapeamento de Equivalência VS Code Tasks ↔ CLI `c2f`
Equipar os agentes com a tabela direta de correlação entre as tarefas do `.vscode/tasks.json` e os comandos nativos do Core CLI `c2f`.
