## 🎯 Objetivo e Diretrizes de Negócio

Eliminar as causas de ambiguidade que levavam agentes de IA a:
1. Criar código HTML/CSS solto ou embutido direto em PHP em vez de usar o **Sistema de Recursos**.
2. Criar strings literais e textos de alertas/erros hardcoded em PHP/HTML/JS em vez de usar o **Sistema de Variáveis e Mensagens Multilíngues (`variables`)**.
3. Criar constantes soltas ou hardcoded em vez de seguir o protocolo oficial de **Variáveis Sensíveis de Ambiente (`.env` / `$_CONFIG`)**.

---

## 📋 Detalhamento das Tarefas de Implementação

### 1. Refatoração de `c2f-global-variables` (`SKILL.md`):
- Mapear a arquitetura completa de superglobais:
  - `$_ENV`: Variáveis de infraestrutura carregadas pelo `Dotenv` a partir de `gestor/autenticacoes/<dominio>/.env`.
  - `$_CONFIG`: Configurações centrais do sistema populadas por `gestor/config.php` (sessões, cookies, segurança CSP/CORS, OAuth, email, etc.).
  - `$_BANCO`: Configurações de conexão (`host`, `nome`, `usuario`, `senha`, `tipo`).
  - `$_GESTOR`: Estado dinâmico do runtime (roteamento, caminhos `ROOT_PATH`/`modulos-path`, URLs, idioma ativo, payloads AJAX).
- Documentar o protocolo de novas variáveis de ambiente: toda nova chave sensível deve ser registrada no template `gestor/autenticacoes.exemplo/dominio/.env` para mesclagem automática no deploy/update.

### 2. Refatoração de `c2f-resources-system` (`SKILL.md`):
- **Remover a ênfase no CLI `upsert-resources.php`**: O agente deve focar na edição direta de arquivos fonte sob `resources/` ou `modulos/<mod>/resources/`, deixando a compilação para o pipeline padrão (`atualizacao-dados-recursos.php` ➔ `*Data.json` ➔ `atualizacoes-banco-de-dados.php`).
- **Cobrir todos os 11+ tipos de recursos**: `pages`, `layouts`, `components`, `templates`, `variables`, `ai_prompts`, `ai_modes`, `ai_prompts_targets`, `forms`, `widgets`.
- **Documentar Extensibilidade Dinâmica de Recursos**: Explicar como tabelas customizadas com `sync_resources: true` (declaradas em `tables_config.json` ou `tabela.config` do módulo) criam novos tipos de recursos dinamicamente com `field_types` (`file:html`, `file:css`, `file:md`, `json`), gerando arquivos `[PascalCase]Data.json`.

### 3. Criação da Skill `c2f-variables-system` (`SKILL.md`):
- **Trigger**: Uso de textos, mensagens de erro, alertas de warning, labels de formulários e strings de interface.
- **Regra Mandatória**: PROIBIDO textos literais fixos em HTML, PHP ou JS.
- **Declaração**:
  - Global: `gestor/resources/<lang>/variables.json`
  - Módulo: `<modulo>.json` (chave `resources.<lang>.variables`)
- **Consumo**:
  - PHP: `gestor_variaveis(['modulo' => 'meu-modulo', 'id' => 'minha-variavel'])`
  - HTML/Templates: `@[[minha-variavel]]@` ou `[[minha-variavel]]` ou substituição via `modelo_var_troca()`.

### 4. Criação da Skill `c2f-environment-configuration` (`SKILL.md`):
- **Trigger**: Adição ou leitura de credenciais, API keys, parâmetros de conexão, flags de ambiente e configurações sensíveis.
- **Protocolo Obrigatório**:
  1. Adicionar ao template `gestor/autenticacoes.exemplo/dominio/.env`.
  2. Mapear em `gestor/config.php` alimentando `$_CONFIG` ou `$_GESTOR`.
  3. Consumir via `$_CONFIG['chave']` ou `$_GESTOR['chave']`.
