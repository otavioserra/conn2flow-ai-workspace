## 🎯 Diagnóstico do Problema

Ao rodar no terminal **Git Bash (MINGW64)**:
1. `c2f.ps1 help` falha porque o Git Bash não busca arquivos `.ps1` sem o prefixo `./` ou o comando `powershell`.
2. `./c2f.ps1 help` falha com `syntax error near unexpected token 'newline' '<#'` porque o interpretador Bash tenta executar sintaxe do PowerShell como script Shell.

No Git Bash / Linux, o executável correto é **`./c2f`** (sem extensão), enquanto no PowerShell é **`.\c2f.ps1`** e no CMD é **`c2f.bat`** / **`c2f.cmd`**.

---

## 📋 Detalhamento das Tarefas de Implementação

### 1. Criar Wrappers Multiplataforma na Raiz de `conn2flow`:
- **`conn2flow/c2f` (Bash / Git Bash / Linux / WSL)**:
  - Assegurar cabeçalho `#!/usr/bin/env bash`, quebras de linha `LF` e permissão `chmod +x`.
  - Execução: `./c2f <comando>` no Git Bash / Linux / Mac.
- **`conn2flow/c2f.bat` & `conn2flow/c2f.cmd` (Windows CMD)**:
  - `@echo off` -> `php "%~dp0cli\c2f.php" %*`.
  - Permite digitar apenas `c2f <comando>` no CMD.
- **`conn2flow/c2f.ps1` (Windows PowerShell)**:
  - Manter suporte ao PowerShell para `.\c2f.ps1 <comando>`.

### 2. Auto-Detecção Inteligente no `c2f.ps1` para Git Bash:
- Adicionar no topo do `c2f.ps1` uma linha de fallback que, se invocado acidentalmente pelo Bash (`./c2f.ps1`), redireciona automaticamente para o PHP em vez de quebrar no comentário `<#`.

### 3. Propagar Executáveis em todos os repositórios alvo:
- Replicar a mesma matriz de wrappers (`c2f`, `c2f.bat`, `c2f.cmd`, `c2f.ps1`) em `lumix`, `transformamp`, `conn2flow-site` e `conn2flow-ai-workspace`.

### 4. Git Staging, Commit e Push:
