## 🎯 1. Contexto & Diagnóstico dos Problemas

### 1.1. Dependência Humana em Validações Visuais e de Runtime
Hoje, a validação de telas e estilos exige que o operador humano inspecione o navegador, copie HTML e relate o que viu. No entanto, o ambiente local Docker possui todas as ferramentas necessárias para que o agente inspecione o runtime sozinho:
* O Core `conn2flow` implementou a função de cookie condicional `gestor_cookie_is_secure()` (relaxando a flag `Secure` em conexões HTTP locais sob `$_GESTOR['development-env'] === true`), viabilizando a persistência de sessão em `curl`, Node e scripts headless.
* O Core CLI disponibiliza os comandos `c2f auth:cookie` (gera tokens JWT de sessão e cookie jar em `temp/agent-cookies.txt`) e `c2f page:inspect <url>` (inspeção headless via CDP/Playwright retornando status HTTP, console errors, `getComputedStyle()`, `getAnimations()` e screenshots).

### 1.2. Mascaramento por Cache Stale de JavaScript (`resources/`)
Quando um agente altera um arquivo `.js` dentro de `resources/<lang>/.../<id>.html/.js`, se a chave `versao` no metadata JSON do recurso ou no manifest do módulo (`<modulo>.json`) não for incrementada (*bump* de versão, ex: `1.0.0` ➔ `1.0.1`), o navegador continua servindo o arquivo antigo em cache.

### 1.3. Bloqueio Indesejado de Leitura de `.env`
Os templates do Claude continham `"permissions": { "deny": ["Read(./.env)", ...] }`, impedindo que os agentes lessem variáveis de ambiente locais essenciais para testes (portas, credenciais de banco e URLs de debug).

### 1.4. Concorrência e Colisões Multi-Agente
Com múltiplos agentes atuando em paralelo, commits com `git add -A` arrastaram alterações de lotes alheios e requisições concorrentes colidiram na numeração de arquivos `req-XXX.md`.

## 🔍 1. Como Funciona o Pipeline de Inspeção Autônoma

No ambiente de desenvolvimento local (`$_GESTOR['development-env'] === true`), o framework disponibiliza ferramentas para que o agente inspecione o runtime de forma 100% autônoma:

### Passo 1: Autenticação de Sessão Server-Side (`auth:cookie`)
Para rotas autenticadas do Gestor (ex: `/admin/`, `/dashboard/`, `/chat-intelligence/`):
```bash
./c2f auth:cookie --user=admin --project=meu-projeto
```
* **O que faz**: Gera o token JWT de sessão server-side e grava o cookie jar em `temp/agent-cookies.txt`.

### Passo 2: Inspeção Headless via CLI (`page:inspect`)
Execute o comando nativo de inspeção:
```bash
./c2f page:inspect "http://localhost/modulo-rota/" --selector=".meu-elemento" --computed="display,opacity,transform" --screenshot
```
* **O que retorna**: JSON estruturado contendo:
  - `status`: Código HTTP (ex: 200, 302, 403).
  - `console_errors`: Array de erros capturados no console do navegador.
  - `computed_style`: Estilos computados resolvidos pelo browser em tempo de execução real.
  - `animations`: Estado das animações CSS ativas (`getAnimations()`).
  - `screenshot`: Caminho do screenshot PNG gerado em `temp/`.

## ⛔ Regras Invioláveis de Inspeção:
1. **EXCLUSIVO PARA AMBIENTE LOCAL DE TESTES**: NUNCA execute inspeção ou scraping automatizado em URLs de produção.
2. **Registro no SDD**: As evidências de inspeção (JSON do `page:inspect` e screenshots) DEVEM ser registradas diretamente no `VALIDATION-CHECKLIST.md` do repositório em vez de marcar "pendente do operador".
3. **Alternância de Ambiente (`c2f env:set`)**:
   - `c2f env:set development`: Força leitura dos arquivos físicos em `resources/`.
   - `c2f env:set production`: Força leitura dos registros compilados no banco de dados.

## 🏷️ 3. Regra Mandatória de Version Bump no Sistema de Recursos

Atualizar as skills **`c2f-resources-system`** e **`c2f-javascript-ajax`** com a regra:
* **Ao alterar qualquer script JavaScript (`<id>.js`) ou folha de estilo em `resources/`**: O agente DEVE OBRIGATORIAMENTE realizar o *version bump* (ex: `versao: "1.0.0"` ➔ `"1.0.1"`) no arquivo de metadados do recurso (`<id>.json`) ou no manifest do módulo (`<modulo>.json`).
* Isso assegura que, ao rodar `./c2f resources:sync`, a query string `<script src="...&v=1.0.1">` seja atualizada, forçando o navegador a invalidar o cache antigo imediatamente.
