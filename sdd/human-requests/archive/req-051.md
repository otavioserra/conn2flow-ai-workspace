# REQ-051 — Feedback Visual de Loading na Extensão, Resiliência de Pipelines VM, Poda de Checklists e Integração de Docs

* **Status**: `APPROVED`
* **Data de Entrada**: 2026-09-03
* **Autor**: Humano-no-Loop & Macro-Arquiteto
* **Lote Relacionado**: `BATCH-053`
* **Topologia de Agentes**: `dupla`
* **Nível de Autonomia**: `supervisionado`
* **Repositórios Alvo**: `conn2flow-ai-workspace` (`vscode-extension`), `conn2flow` (Core CLI) e satélites (`conn2flow-site`, `lumix`, `transformamp`)
* **Origem no Backlog**: Consolição de `FEAT-008`, `FEAT-011`, `ARCH-006` e `FEAT-007`

---

## 1. Justificativa e Objetivos de Negócio

Esta requisição unificada consolida as últimas 4 melhorias ativas do Backlog:
1. **Feedback Visual Contínuo (`FEAT-008`)**: Eliminar a sensação de tela travada em ações longas da extensão (como release, compilação de CSS e updates de projetos), fornecendo feedback de loading e progresso nativo no VS Code.
2. **Resiliência em Ambientes VM (`FEAT-011`)**: Corrigir a saída silenciosa do atualizador via API (`update-system.sh`) em domínios `.local` com certificados autoassinados da VM (flags cURL `--insecure` e logs detalhados) e adaptar a árvore Dev Tools para ocultar diagnósticos Docker quando o ambiente ativo for VM.
3. **Poda SDD de Checklists Históricos (`ARCH-006`)**: Podar os blocos antigos em `VALIDATION-CHECKLIST.md` dos repositórios para `sdd/validation/archive/`, mantendo os índices leves e alinhados à política de contexto.
4. **Integração Documental Ampla (`FEAT-007`)**: Expor guias arquiteturais consolidados em `ai-workspace/docs` diretamente na árvore do painel Dev Tools do VS Code.

---

## 2. Escopo Técnico da Entrega

### 2.1 Feedback Visual e Loading na Extensão VS Code (`FEAT-008`)
- Em `vscode-extension/src/`:
  * Envolver ações longas em `vscode.window.withProgress({ location: vscode.ProgressLocation.Notification, cancellable: false }, ...)` ou barra de status animada.
  * Cobrir:
    - *"Salvar e Executar"* no `releaseManager.ts` / formulário de release;
    - Execuções de pipeline no `coreCommands.ts` (`manager:update-all`, `resources:sync`, `css:rebuild`);
    - Comandos de projetos satélites em `projectsManager.ts` (`project:update-all`, `project:deploy`, `project:sync-core`);
  * Atualizar o botão/painel para exibir estado de carregamento durante a execução e emitir mensagem clara ao concluir.

### 2.2 Resiliência de Pipelines para VM e API Updater (`FEAT-011`)
- No Core (`conn2flow/ai-workspace/en/scripts/projects/update-system.sh` e `ProjectUpdateSystemCommand.php`):
  * Adicionar flag cURL `-k` / `--insecure` quando a URL contiver `.local` ou for configurada com SSL local de desenvolvimento na VM.
  * Exibir o corpo da resposta HTTP / JSON de erro e código de status caso o Step 1/4 (`Starting update session...`) ou passos subsequentes falhem.
- Na Extensão VS Code (`vscode-extension/`):
  * Na seção `🩺 Diagnóstico & Infraestrutura`, ocultar comandos de Docker (como logs do container ou status Docker) quando o projeto ativo configurado no `environment.json` tiver `deploy_mode: "ssh"` ou operar em ambiente VM.

### 2.3 Poda SDD dos Checklists Históricos nos Satélites (`ARCH-006`)
- Em `conn2flow`, `lumix` e `transformamp`:
  * Arquivar lotes antigos de validação em `sdd/validation/VALIDATION-CHECKLIST.md` que excedam 25 itens ativos para subpastas `sdd/validation/archive/`.
  * Preservar os lotes recentes no arquivo ativo, mantendo a integridade de links relativa.
  * Validar paridade das 36 skills com `php cli/c2f.php ai:sync`.

### 2.4 Integração de Documentação Ampla (`FEAT-007`)
- Na seção `📚 Documentações & Configurações` do `conn2flowTreeProvider.ts`:
  * Adicionar nós apontando para os guias de arquitetura em `docs/pt-br/` e `docs/en/` (ex: Arquitetura de Agente Duplo).
  * Garantir tooltips explicativos e localização bilingue (`package.nls.json` e `package.nls.pt-br.json`).

## 3. Critérios de Aceite

1. **Loading Visível**: Execuções de release e update exibem barra de progresso nativa no VS Code e finalizam com notificação informativa.
2. **Atualizador de API Verboso e Resiliente**: `c2f project:update-system` aceita conexões locais `.local` com certificados autoassinados da VM e reporta erros de HTTP detalhadamente sem abortar silenciosamente.
3. **Árvore Dev Tools Adaptada**: Nós de Docker ocultados ou contextualizados em projetos VM.
4. **Checklists Podados**: `VALIDATION-CHECKLIST.md` nos satélites com apenas os lotes recentes e histórico preservado em `archive/`.
5. **Testes Verdes**: `npm test` na extensão em 100% verde e `php cli/c2f.php ai:sync` com 36/36 skills nos repositórios.
6. **Recibo MCP**: Emitir `completions/BATCH-053-executor-receipt.json`.
