## 1. O problema, medido

Durante a homologação da req-092 (`lumix`), o operador relatou que o efeito de digitação
(*typewriter*) "não fazia o efeito, imprimia a resposta inteira". Não era defeito: o código pula a
animação sob `prefers-reduced-motion: reduce`, como a própria §3.1 da req-092 manda.

Medido com o código real da página, nas duas condições:

| `prefers-reduced-motion` | `startTypewriter()` | o que aparece |
| --- | --- | --- |
| `true` | `NULL` | texto inteiro de uma vez |
| `false` | `INICIOU` | revelação progressiva |

**A causa estava na estação do operador**, e o diagnóstico exigiu distinguir duas configurações do
Windows que costumam ser confundidas:

| configuração | API | estado medido | o Chrome usa? |
| --- | --- | --- | --- |
| Animações de janela | `MinAnimate` (registro) | LIGADO | **não** |
| **Efeitos de animação** (Acessibilidade > Efeitos visuais) | `SPI_GETCLIENTAREAANIMATION` (`0x1042`) | DESLIGADO | **sim** |

É a segunda que define `prefers-reduced-motion`. No Windows 11 ela vem **ligada de fábrica**.

### Por que isso não se resolve no navegador

O DevTools do Chrome oferece apenas **"No emulation"** e **"prefers-reduced-motion: reduce"** — não
existe opção para forçar `no-preference`. A flag de linha de comando também só existe no sentido
restritivo (`--force-prefers-reduced-motion`). Ou seja: **não há como testar o caminho animado sem
alterar a configuração do sistema**.

### Por que o operador desligou

Por desempenho e usabilidade do sistema operacional (a animação de troca de área de trabalho
virtual, entre outras) — **não** por sensibilidade a movimento. É um caso comum, e faz o
`prefers-reduced-motion` comunicar ao site uma intenção que o usuário não teve no contexto web.

## 2. Frente 1 — Comando `c2f` (repositório `conn2flow`)

Comando novo, no padrão dos já existentes (`env:set`, `auth:cookie`, `page:inspect`):

```bash
c2f motion:status     # mostra o estado atual
c2f motion:on         # liga  -> prefers-reduced-motion = no-preference
c2f motion:off        # desliga -> prefers-reduced-motion = reduce
```

Aliases sugeridos: `motion:toggle`, `anim:on`, `anim:off`.

### Implementação de referência, já validada nesta máquina

O Executor testou o mecanismo ponta a ponta (ligou, confirmou por leitura, e reverteu). O núcleo é:

```powershell
# SPI_GETCLIENTAREAANIMATION = 0x1042 ; SPI_SETCLIENTAREAANIMATION = 0x1043
# SPIF_UPDATEINIFILE | SPIF_SENDCHANGE = 3   (persiste e notifica as janelas abertas)
$sig = @"
[System.Runtime.InteropServices.DllImport("user32.dll", EntryPoint="SystemParametersInfoW", SetLastError=true)]
public static extern bool SetB(uint uiAction, uint uiParam, System.UIntPtr pvParam, uint fWinIni);
[System.Runtime.InteropServices.DllImport("user32.dll", EntryPoint="SystemParametersInfoW", SetLastError=true)]
public static extern bool GetB(uint uiAction, uint uiParam, ref bool pvParam, uint fWinIni);
"@
$api = Add-Type -MemberDefinition $sig -Name SPIAnim -Namespace C2F -PassThru

# ler
$v = $false; $null = $api::GetB(0x1042, 0, [ref]$v, 0)

# escrever (1 = ligado, 0 = desligado)
$null = $api::SetB(0x1043, 0, [System.UIntPtr]::new(1), 3)
```

Um script funcional está em
`scratchpad/animacoes.ps1` da sessão do Executor e pode ser aproveitado integralmente.

### Cuidados que a implementação precisa respeitar

1.  **Mexer SOMENTE em `SPI_SETCLIENTAREAANIMATION`.** Não tocar em `MinAnimate` nem em
    `UserPreferencesMask`: o operador desligou as animações de janela de propósito, e alterá-las
    junto (foi o erro cometido pelo Executor antes de medir) muda o comportamento do sistema todo.
2.  **`EntryPoint="SystemParametersInfoW"`.** Declarar o método com outro nome causa
    `EntryPointNotFoundException` — não existe `SystemParametersInfoGet` na `user32.dll`.
3.  **Avisar que a aba precisa ser recarregada**: o Chrome relê a preferência na carga da página.
4.  **Multiplataforma**: em Linux/GNOME o equivalente é
    `gsettings set org.gnome.desktop.interface enable-animations true|false`; em macOS,
    `defaults write com.apple.universalaccess reduceMotion -bool`. Fora do Windows o comando pode
    apenas reportar "não suportado neste sistema" numa primeira versão, desde que diga isso
    claramente em vez de falhar em silêncio.
5.  **Nunca deixar o estado alterado sem aviso.** O comando é reversível por natureza, mas quem o
    usa dentro de uma automação precisa restaurar (ver Frente 2).

## 3. Frente 2 — Skill `c2f-agent-visual-inspection` (repositório `conn2flow-ai-workspace`)

A skill já existe e cobre `auth:cookie` + `page:inspect`. Falta o procedimento de animação:

1.  **Validar nos DOIS estados**, quando o alvo for animação CSS: com `motion:off` e com
    `motion:on`. Um lote que só testa um dos lados deixa passar exatamente os dois defeitos reais
    já encontrados neste projeto — indicador parado sob `reduce` (req-091) e typewriter ausente
    sob `reduce` (req-092).
2.  **Registrar o estado no `VALIDATION-CHECKLIST`**, junto da evidência, para que a leitura futura
    saiba em qual condição a medição foi feita.
3.  **Restaurar o valor original ao final**, sempre — inclusive em caso de erro no meio. A skill
    deve declarar isso como regra inviolável, no mesmo tom das outras.
4.  Convém a skill registrar também a distinção entre as duas configurações do Windows (seção 1
    desta requisição): foi o que custou tempo no diagnóstico.

## 4. Frente 3 — Preferência do efeito de digitação (repositório `lumix`)

Hoje o Chat Intelligence decide só por `prefersReducedMotion()`. Proposta: uma preferência do
usuário, com três estados, tendo o sistema como padrão:

| valor | comportamento |
| --- | --- |
| `sistema` (padrão) | segue `prefers-reduced-motion`, como hoje |
| `sempre` | anima mesmo com `reduce` no sistema |
| `nunca` | nunca anima, mesmo sem `reduce` |

### Por que isso é legítimo, e não um contorno

Respeitar `prefers-reduced-motion` continua sendo o **padrão**. O que a preferência acrescenta é uma
**escolha explícita** de quem desligou animações por desempenho do sistema e ainda assim quer o
efeito no chat. Um override silencioso seria errado; um seletor que a pessoa opera, não.

### Onde encaixa

- Persistência em `user-configs` (o módulo já existe e guarda preferências por usuário).
- `prefersReducedMotion()` passa a consultar a preferência antes do media query.
- **A mesma preferência deve valer para o indicador de digitação** (as três bolinhas), que hoje cai
  na variante `chat-intelligence-fade` sob `reduce` — senão o usuário liga o typewriter e as
  bolinhas continuam no modo reduzido, o que é incoerente.
- Testes: os três estados, e a garantia de que `sistema` preserva exatamente o comportamento atual.
